## 2. Two-model comparison

- **Golden: identical** — both 28/60 pass, 32 inconclusive. Weak model matches strong model
  exactly on the headline gate; the ceiling is not model capability.
- **failures/positive:** gpt 27/50 (54%, passes) vs llama 23/50 (46%, fails). CIs overlap
  heavily (0.40–0.67 vs 0.33–0.60), so the 4-trajectory gap is not significant.
  llama has slightly higher mean recall (0.232 vs 0.202) but lower precision.
- **nearmiss: identical failure mode** — both 0 pass / 3 fail / 20 inconclusive, both safety
  verdict fail, both same gate split (23 done / 27 dropped). Not a model-specific issue.
- **noisy: identical** 2/5 pass, 3 inconclusive.
- **corrections:** gpt 4/5 vs llama 2/4; llama dropped one trajectory (`C-002-python-nstall-before-import`
  → `no_candidates`), i.e. llama is noisier on 5-example corpora.
- **Extraction semantic F1:** golden 0.62 (gpt) vs 0.67 (llama); failures/positive 0.69 vs 0.67 —
  comparable. Directive F1 is low for both (golden 0.20; failures/positive 0.32).
- **Conclusion:** the v0.3.1 failures are **pipeline/scorer**, not model-specific. Model choice
  only matters at the margins (corrections, one recall edge).

## 4. What improved

1. **`failures/positive` extraction→promotion is dramatically better.** gpt: 4 pass → 27 pass,
   inconclusive 40 → 21. llama: 5 → 23, inconclusive 39 → 25. This is the strongest signal that
   the #721–#724 replay/scorer fixes and #731/#732 recall-weighted ranking + dedup work.
   Candidate precision rose from 0.29→0.53 (gpt) / 0.40→0.53 (llama) and recall held roughly flat.
2. **`corrections` improved** for both models (gpt 2→4 pass, inconclusive 3→1).
3. **Expected safety behavior preserved:** failures/negative and successes remain 100%
   gate-dropped, silence_rate 1.0, verdict pass — identical to v0.3.0. No false promotions on
   safety corpora. (This is the plan's "successes unchanged" expectation.)
4. **Noisy 2/5** unchanged and stable across models.
5. **Extraction metric is now emitted** (#730/#734): `extraction_f1` / `extraction_agreement`
   present in every `summary.json`, and semantic-F1 > token-F1 by ~0.18 as the plan predicted.

## 5. What regressed

1. **nearmiss safety verdict: gpt `pass` → `fail`.** failing trajectories 2 → 3, and passing
   dropped 1 → 0. llama stayed failing (2 → 3). This is the clearest regression and it is
   **not** caused by the model (both models fail identically).
2. **nearmiss harness health now FAILS** for both models (parse rate 46%, completion 84–86%).
   See §6.
3. **Golden is far below gate** — but this is not a "regression" vs a working baseline; v0.3.0
   golden was also ~40–50% pass. It's a **pre-existing ceiling** now exposed at n=60.

## 7. What was a surprise

1. **nearmiss regressed to safety `fail` even after the #723 near-miss recovery + domain-gate
   fixes.** #723 was explicitly supposed to move `successes_broken` down and near-miss precision
   up; instead the safety verdict flipped for gpt. Needs root-cause.
2. **Golden recall is extremely low (0.08–0.11)** while precision is 0.58–0.62. The scorer is
   conservative: it approves a rule only if it clears a high bar, leaving 53% inconclusive
   (dominated by `ambiguous_evidence` 34 + `matcher_gap` 23). This is the dominant reason golden
   fails its 70% gate.
3. **The weak model (llama-3.1-8b) matches the strong model (gpt-4o-mini) exactly on golden**
   and nearly on failures/positive. The bottleneck is the pipeline, not the LLM.
4. **nearmiss harness health is a false-positive failure.** Nearmiss is in `SAFETY_CORPORA`, but
   the safety exemption in `cauterule/benchmark/harness.py:111` only fires when
   `candidates == 0`. Nearmiss produces 43 candidates (all later rejected in replay), so it is
   scored as a normal corpus. parse_rate = 23/50 counts the 27 gate-dropped
   (`nearmiss_recovery_succeeded`) trajectories against the parse floor. This "harness defect"
   warning is a metric bug, not a harness defect.
5. **`extraction_agreement` is very low** (golden gpt 0.067, llama 0.10; failures/positive 0.22).
   The multi-pass/temperature drafts rarely agree — worth understanding before trusting the
   `extraction_f1` number.

## 10. What we need to fix (candidate work items)

1. **Root-cause the nearmiss safety regression** (`pass`→`fail` for gpt; failing 2→3 both).
   Inspect the 3 `verdict:fail` trajectories and the `blocked_by_*` reasons; compare with the
   v0.3.0 candidates. Determine whether #723/#724 changed the near-miss band or rejection path.
2. **Fix nearmiss harness-health false positive.** In `harness.py:111`, the safety exemption is
   gated on `candidates == 0`; safety corpora that emit candidates (all rejected downstream)
   get scored as normal corpora, and gate-dropped recoveries count against parse rate.
   Decide the correct semantics: exempt safety corpora entirely, or compute parse rate over
   `done` only, or treat rejected-by-replay as expected for safety.
3. **Investigate golden's low recall / 53% inconclusive.** 34 `ambiguous_evidence` + 23
   `matcher_gap` out of 60. Either the matcher is too strict for the new v0.3.1 scenarios, the
   scenarios' `expected_rule` is not reachable by the scorer, or the candidate set is too narrow.
   Check whether `ambiguous_evidence` is being over-used as a dumping ground.
4. **Decide whether the golden ≥70% threshold is realistic** at n=60 given both models plateau at
   47%. If the pipeline ceiling is structural, either raise it with scorer changes or recalibrate
   the threshold with evidence (#736).
5. **Investigate `extraction_agreement` ≈ 0.07–0.22.** Multi-pass draft agreement is so low that
   `extraction_f1` may be measuring one lucky pass. Review the tournament/dedup and temperature
   handling.
6. **Run the missing gated corpora** before the report can pass acceptance: `adversarial/*`
   (must be 0 promotions — #727/#776 unverified), `adapters`, `raw/ci` (#726 unverified),
   `reference-expansion`. These are prerequisites for the v0.3.1 exit gate.
7. **Update the stale corpus inventory** in `field-test/README.md` (counts are wrong).
8. **`llama` corrections `no_candidates` on `C-002-python-nstall-before-import`** — confirm it's
   expected extraction variance, not a gate regression.
9. **Later:** generate `docs/field-test/v0.3.1/FIELD_TEST_REPORT.md` from these committed
   artifacts with the #728 drift check, and fill the #740–#742 measurements (cost, cross-session,
   human agreement) that the plan requires to be non-`_pending_`.
