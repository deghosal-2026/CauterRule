**Date:** 2026-09-05
**Milestone:** M30 — Comprehensive Field Test (42 open issues on GitHub)
**GitHub:** https://github.com/deghosal-2026/CauterRule/milestone/31

---

## 1. Objective

Validate the full CauterRule system end-to-end across multiple environments, failure domains, and agent types. Confirm that the extract → test → promote → inject loop measurably reduces repeat failures, that replay is deterministic and safe, and that the system is ready for production use.

The field test is the final gate before release. If the field test fails, the system is not ready for v0.1.0. If it passes, we proceed to M31 (Release Readiness) and M32 (Release).

The field test uses three corpus sources, each serving a different purpose:

| **Generated trajectories** | `field-test/v0.1.0/trajectories/` | Single-agent field tests with real agent failures | Yes |

### 3.2 Test Fixture Trajectories (5 files)

|------|----------|--------|---------------|---------------|

# Generate domain-specific trajectories

corpus = build_tiered_corpus('corpus/public', {'tiny': 25, 'small': 100, 'medium': 1000}, seed=42)
for tier, trajs in corpus.items():

**What:** Fail in session 1, verify promoted rule prevents the same failure in a fresh session 2.

**Corpus:** 3 tasks from the coding agent harness
**LLM:** GPT-4o (session 1 only)
**Duration:** ~20 minutes (2 sessions)

**Steps:**
1. Session 1: Run 3 tasks that fail, extract, promote rules
2. Close session (rules persisted to `rules/` directory)
3. Session 2: Open fresh Python process, load rules from store
4. Run the same 3 tasks with rules injected
5. Verify all 3 failures are prevented

**Acceptance Criteria:**
- [ ] Rules promoted in session 1 persist to disk (YAML files)
- [ ] Rules load correctly in fresh session 2
- [ ] `cauterule inject` shows rules in session 2
- [ ] All 3 failures prevented in session 2
- [ ] Rule store is identical across sessions (same rule files)

### 7.6 Task 30.3.6: Run Long-Horizon Field Test (#251, #26)

**What:** Run 20-50 step tasks with late-stage failures; verify rules still help when failures occur deep in the trajectory.

**Corpus:** 2 long-horizon tasks (20+ steps each)
**LLM:** GPT-4o
**Duration:** ~15 minutes

**Steps:**
1. Run 2 tasks with 20+ steps each
2. Failures occur at step 15+ (late in trajectory)
3. Extract rules from the late failures
4. Verify extraction identifies the correct root cause despite long trajectory
5. Re-run with rules injected

**Acceptance Criteria:**
- [ ] Extractor identifies correct root cause in 20+ step trajectories
- [ ] Rules extracted from late-stage failures are specific (not generic)
- [ ] Rules fire on re-run and prevent the late-stage failure
- [ ] Extraction success rate for long-horizon ≥70%

### 7.7 Task 30.3.7: Run Noisy Trajectory Field Test (#252, #27)

**What:** Inject retries, irrelevant tool calls, and distractions; verify extractor still finds the correct lesson.

**Corpus:** 5 noisy trajectories (with retries, irrelevant calls)
**LLM:** GPT-4o
**Duration:** ~10 minutes

**Steps:**
1. Create 5 trajectories with noise (3+ retries, 2+ irrelevant tool calls)
2. Extract rules from each noisy trajectory
3. Compare extracted rules with rules from clean versions of same trajectories
4. Verify extractor identifies the real root cause despite noise

**Acceptance Criteria:**
- [ ] Extractor identifies correct root cause in ≥80% of noisy trajectories
- [ ] Extracted rules from noisy trajectories match rules from clean trajectories
- [ ] Noise does not cause false positive extractions
- [ ] Confidence scores for noisy trajectories are lower but still above threshold

### 7.8 Task 30.3.8: Run Human-Correction Field Test (#253, #28)

**What:** User types "next time do X" after a failure; verify correction is converted, tested, and promoted.

**Corpus:** 5 human corrections
**LLM:** GPT-4o (for extraction from correction text)
**Duration:** ~10 minutes

**Steps:**
1. Run 5 tasks that fail
2. For each failure, provide a human correction: "next time, pull before pushing"
3. System converts correction to CandidateRule via `cauterule extract --correction`
4. Replay-test each candidate
5. Promote passing candidates
6. Re-run tasks to verify corrections prevent failures

**Acceptance Criteria:**
- [ ] Human corrections converted to CandidateRules with specific triggers
- [ ] ≥4 of 5 corrections pass replay testing
- [ ] ≥4 of 5 corrections promoted to rule store
- [ ] Corrections prevent the original failures on re-run
- [ ] Correction triggers are specific (not "when git fails" — should be "when git push fails with non-fast-forward")

## 12. Reproduction Instructions

To re-run the entire field test:

```bash
# 1. Clone and install
git clone https://github.com/deghosal-2026/CauterRule.git
cd CauterRule
pip install -e ".[dev]"

# 2. Generate corpus
python -c "from cauterule.corpus.tiers import build_tiered_corpus; build_tiered_corpus('corpus/public', {'tiny': 25, 'small': 100, 'medium': 1000}, seed=42)"

# 3. Run Phase 1 (hermetic, no LLM)
pytest tests/ -v -m "not slow"
pytest tests/scale/ -v
pytest tests/adversarial/ -v
pytest tests/field/ -v

# 4. Run Phase 2 (benchmarks, needs LLM for bake-off)
pytest tests/benchmark/ -v
python -c "from cauterule.benchmark.bakeoff import BakeoffHarness; ..."  # Set API keys

# 5. Run Phase 3 (single-agent, needs LLM)
python field-test/v0.1.0/harness.py  # Set CAUTERULE_LLM_PROVIDER and API keys

# 6. Run Phase 4 (multi-env)
docker build -t cauterule:field-test .
docker run --rm cauterule:field-test demo
pytest tests/field/test_docker_multienv.py -v

# 7. Generate Phase 5 (reporting)
# Manually create field-test/v0.1.0/FIELD_TEST_REPORT.md from results
```

**Environment variables needed:**
```bash
export CAUTERULE_LLM_PROVIDER=openai      # or anthropic, ollama, litellm
export CAUTERULE_MODEL=gpt-4o             # or claude-sonnet-4, llama3.1
export OPENAI_API_KEY=sk-...              # for OpenAI
export ANTHROPIC_API_KEY=sk-ant-...       # for Anthropic
# Ollama runs on localhost:11434 — no key needed
```
